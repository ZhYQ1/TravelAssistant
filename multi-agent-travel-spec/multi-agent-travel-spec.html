01 / CONTEXT & SCOPE

背景、目标与范围

本 Spec 将已提供的项目实践整理为可评审、可实现、可验收的技术契约。它不是对现有代码的反演：工作区未提供实现代码，因此物理类名、Key、阈值和配置项均须以代码评审结果为准。

已确认输入三级意图识别、Jev 快速判定、三类 Agent、Redis 方案中转、多方案审核编排、AgentScope Hook、活跃子智能体续跑、SkillContentCollapseHook，以及文中的性能数据，均来自项目描述。[1]

待评审设计为补齐端到端闭环，本文定义逻辑字段、状态、失败恢复和验收口径；这些设计不宣称已在现有系统落地。

TBD所有未提供的阈值、权重、TTL、重试次数和性能目标，不在本文中虚构具体值。

1.1 问题与系统回应

已观察问题影响本 Spec 的系统回应
口语、省略和歧义表达导致意图冲突，统一 LLM 路由成本高误路由、路由延迟与 Token 消耗偏高L1 规则反向排除 → L2 向量候选 → L3 模型判定；Jev 承担类型化快判，低置信度回退 LLM
完整行程经对话上下文传递时丢失交通、酒店候选审核输入不完整，结论不可信或无法复现完整方案写入 Redis，上下文只传引用；ReviewTool 按约定 Key 读取并校验版本
多个候选方案缺少统一审核与整改顺序规划、审核与复审脱节审核编排器统一评估体验、韧性、偏好，并结合历史结果生成整改优先级
第三方 CLI 授权依赖节点本地登录态跨节点漂移、用户间状态串扰、执行目录冲突AgentScope Hook 统一适配，按用户注入 API Key，隔离执行目录与 Redis 状态
“确认、修改”等闭环指令重新经过主 Agent 调度重复识别与重复调度，续跑直达率下降按对话阶段生成动作词表，合法点击直接续跑当前活跃子 Agent
历史 Skill 内容持续占用上下文，动态时间污染静态前缀上下文膨胀，KV Cache 复用受限超轮次折叠历史 Skill 内容；静态 Prompt 与动态时间解耦

1.2 产品契约与完成条件

主要用户是发起差旅规划、咨询、修改或确认的差旅用户。系统从一条自然语言输入或闭环动作开始，完成条件因任务类型而异：

  • 任务协调：得到可审核的完整行程方案，经过必要的整改与复审后达到“审核通过”，或由用户明确终止。
  • 知识咨询：返回与问题匹配的知识答案，不触发行程状态变更或外部副作用。
  • Workflow：进入匹配的确定性流程并返回该流程的结构化结果；流程失败时给出可恢复状态。

1.3 范围边界

P0：本 Spec 覆盖

  • 三级意图识别、置信度回退与三类 Agent 路由
  • 完整方案中转、多方案审核、整改与复审
  • 外部 Skill 授权、目录与状态隔离
  • 阶段化动作推荐与活跃子 Agent 直达
  • Skill 内容折叠、静态/动态 Prompt 解耦
  • 上述链路的日志、异常恢复和回归验收

不在本文定义

  • 机票、酒店真实下单、支付、退改与发票流程
  • 差旅制度本身及具体规则条款
  • Jev、向量模型或 LLM 的训练方案
  • 第三方 Skill 的内部业务实现
  • 组织排期、上线批次与人员分工
  • 未提供依据的 SLA、准确率或缓存命中率数值

03 / INTENT & ROUTING

三级意图识别与多 Agent 路由

路由采用成本递增、置信度驱动、同构输出的判定链。任一层只有在输出满足该层确定性条件时才可直接生效，否则继续下沉；所有路径最终都归一化为 RouteDecision。

集成关系待确认为保持“三级”定义，本文将 L3 定义为模型判定层，内部包含 Jev 快判与 LLM 精判兜底。若现状把 Jev 作为独立串联阶段，应调整层级命名，但不得改变“低置信度回退 LLM”和统一输出契约。[Assumption, TBD]

3.1 分层处理规则

ID层级触发与处理规则输出/状态变化异常与边界
FR-R01输入规范化保留原始输入，同时构造供规则与模型使用的规范化视图；不得因省略补全而覆盖原文生成路由上下文与追踪 ID缺少关键任务参数时允许直接澄清，不强行路由执行任务
FR-R02L1 规则先识别“不是、别、不用”等反向排除语义，再处理正向命中；被排除意图不得因另一关键词命中而直接胜出无冲突时直接返回目标类型及规则 ID多意图仍冲突、正负规则矛盾时下沉 L2；冲突不得静默忽略
FR-R03L2 向量L1 未决时召回候选意图并排序；候选区分度阈值 [TBD]满足条件则返回候选及分数，否则携带候选进入 L3空召回、向量服务超时或分数不可用时进入 L3，并记录降级原因
FR-R04L3-a Jev将路由建模为选项、评分或布尔任务；输出必须含目标值与置信度概率，置信度阈值 [TBD]高置信度直接路由；低置信度进入 LLM 精判非法枚举、缺失置信度、超时均视为未决，不得当作高置信度结果
FR-R05L3-b LLM接收原输入、必要上下文和 L2/Jev 候选，输出与 Jev 同构的受约束结果合法结果归一化后路由，并标记 fallback=true输出非法、超时或仍无法区分时返回澄清；单次路由最多一次 LLM 精判，避免回退环
FR-R06审计记录判定层、规则/候选、置信度、回退原因、延迟、Token、目标 Agent 和追踪 ID形成可重放的路由观测记录日志不得记录 API Key；敏感原文的脱敏与留存周期 [TBD]

3.2 反向排除与歧义消解

L1 的反向排除词不是普通负向关键词计数，而是意图资格的约束。例如“不是查政策，直接帮我改行程”中，“查政策”处于排除域，知识咨询不得仅凭该词组命中；修改行程仍须通过后续正向条件确认。该例只说明规则语义，具体词表及优先级配置为 [TBD]。

  • 排除域必须有明确作用范围，不能因句首“不是”而排除整句全部意图。
  • 同时存在两个未排除且都需要执行的任务时，应返回多任务协调或澄清，其选择策略为 [TBD]。
  • 规则命中必须输出规则 ID 与排除依据，以支持固定集回归和误路由复盘。

3.3 Jev 类型化任务契约

输出类型适用路由问题必需结果回退条件
选项三类 Agent 或候选 Workflow 中选择一类受限枚举值、置信度枚举越界、最高置信度低于阈值、候选并列处理失败
评分对 L2 候选进行可比较评分候选分数集合、置信度候选缺失、分数非法、无法形成可接受区分度
布尔判断是否续跑当前活跃 Agent 等二分类判定布尔值、置信度非布尔输出、低置信度或活跃会话上下文缺失

3.4 路由输出与已提供实测

RouteDecision 至少应表达：route_type、target_agent、confidence、decision_layer、fallback、fallback_reason、clarification、trace_id。这些为逻辑名称，代码字段映射为 [TBD]。

结果口径：60 条口语/省略/歧义固定回归集，2 轮对比；平均路由延迟 1189.8ms → 547.2ms，P95 延迟下降 61.9%，平均 Token 消耗下降 27.8%。[1]

解释边界：原始 P95 数值、Token 统计范围、准确率与置信区间未提供，不能从现有降幅反推，也不将上述实测值直接写为未来环境 SLA。

04 / PLAN & REVIEW

规划审核链路与审核决策闭环

本模块的核心不变量是：审核必须读取完整、同版本、可追溯的方案，而不是依赖被压缩的对话上下文。对话上下文只承担引用与协调信息，完整交通/酒店候选以 Redis 中的版本化方案为准。

4.1 完整方案中转与读取

ID要求处理规则禁止行为
FR-P01先持久化后发布引用规划 Agent 完整写入方案并确认可读后，才能把 plan_ref + version 发布到对话上下文禁止先返回引用再异步补齐关键候选
FR-P02完整性校验ReviewTool 读取后校验计划归属、版本及必需候选集合；缺项返回 DATA_INCOMPLETE禁止把“候选缺失”误判为“候选不合规”
FR-P03版本不可变任何修改、整改或重规划都生成新版本；审核报告绑定输入版本禁止审核期间覆盖同 Key 的同版本内容
FR-P04可恢复读取Key 缺失/过期时，由编排器请求规划侧重新提交或从权威来源恢复；恢复策略 [TBD]禁止仅凭对话摘要补造交通、酒店候选
FR-P05隔离与生命周期Redis 逻辑 Key 至少能隔离用户/会话、计划和版本；物理 Key、TTL、序列化格式 [TBD]禁止跨用户读取或把凭证写入方案数据

4.2 多方案审核编排

审核编排器从 Redis 取得一个或多个完整方案，调用规则引擎进行统一评估，并汇总历史审核结果生成整改优先级。规则命中证据、规则版本与输入方案版本必须同时保存，以支持复审与差异比较。

评估维度输入输出待确认规则
差旅体验交通与酒店候选、日程衔接、用户时间约束体验问题、命中规则、影响说明体验指标、权重、硬性时间约束
行程韧性换乘/衔接信息、候选可替代性、计划中的风险信息韧性风险、可替代候选或整改建议韧性评分模型、风险阈值、替代方案条件
用户偏好本次偏好与经授权可用的历史偏好快照偏好命中/偏离项偏好优先级、冲突处理和授权范围
历史审核结果与当前用户/任务相关且可合法使用的历史问题及整改结果重复问题信号、整改优先级的调整依据历史窗口、相似问题定义、加权方式、数据保留期

算法待定整改优先级必须采用可解释、可复现的确定性排序，但严重度、体验、韧性、偏好和历史重复问题的权重均未提供。本文不指定虚构公式；实现前须由评审确定排序键、并列处理和最低整改条件。

4.3 审核状态机与复审

FR-V03历史结果可比较能够识别同一问题在新版本中已解决、仍存在或新增，具体相似规则 [TBD]
FR-V04防止无限闭环最大整改/复审轮次及超限处理为 [TBD]；超限后必须请求用户决策或人工介入，不得静默循环

05 / SKILL ADAPTER

外部 Skill 统一接入与隔离

基于 AgentScope Hook 建立统一适配层，将第三方 CLI 的授权与状态管理从节点本地环境中解耦。一次 Skill 执行必须显式携带用户级凭证、独立执行目录和独立状态命名空间，不得依赖上一次调用或某一节点残留的登录态。

5.1 Hook 执行契约

  1. 调用前：解析与隔离。校验用户身份和执行上下文；按用户解析 API Key；创建或绑定本次独立执行目录；构造用户/会话级 Redis 状态命名空间。凭证通过受控注入方式传给进程，注入机制为 [TBD]。
  2. 执行中：显式传递。第三方 CLI 只在指定目录运行，只访问本次授权的状态命名空间；跨节点调度时重新构造同一逻辑执行上下文，而不是复制节点登录文件。
  3. 调用后：归一化与清理。把第三方输出映射为统一成功/失败/需授权状态，记录执行 ID、耗时和脱敏错误；临时文件清理与保留策略为 [TBD]，API Key 不进入日志、对话或 Redis 方案数据。
ID能力强制要求失败处理
FR-S01用户级授权API Key 按用户注入；不同用户不得共用默认凭证；优先不落地，具体密钥管理方案 [TBD]缺失、过期或拒绝时返回明确授权错误，不切换到他人或节点凭证

06 / DIRECT CONTINUATION

闭环推荐与跨 Agent 续跑

系统按对话阶段推荐“确认、修改”等动作词表。点击动作不是普通文本消息的替代品，而是一个带有活跃 Agent 引用、当前任务版本和动作语义的结构化续跑请求。

6.1 推荐与直达流程

  1. 阶段识别。主 Agent 或任务协调 Agent 根据当前活跃任务生成允许动作集合；词表、展示文案与阶段映射可配置，具体配置为 [TBD]。
  2. 动作绑定。前端动作载荷绑定 session_id、active_agent_id、task_id、可选 plan_ref + version、action 和幂等点击 ID。
  3. 服务端校验。检查活跃会话是否有效、动作是否允许、计划版本是否匹配，以及用户是否有权操作该会话。
  4. 直达或回退。校验通过则直接续跑当前活跃子 Agent，不再经过主 Agent 的重复路由；失效、越权或版本冲突时返回主路由/澄清路径，并说明原因。
ID要求通过条件回退条件
FR-C01阶段化词表只推荐当前状态允许执行的动作；不同状态不会展示互相矛盾的确认/修改动作无活跃任务时不生成续跑动作，转为普通输入路由
FR-C02活跃 Agent 直达合法点击在不重复主路由的情况下定位同一子 Agent 和任务会话过期、Agent 已结束或上下文不完整
FR-C03版本保护“确认”只作用于用户看到的同一计划版本版本不一致时禁止确认旧方案，要求查看最新版本
FR-C04幂等点击同一点击 ID 重发不重复触发副作用重复 ID 返回首次执行状态或处理中状态
FR-C05跨团队接口前端、主 Agent、子 Agent 对动作枚举、状态与错误码使用同一契约未知动作不得当作自由文本执行，应返回不支持或进入明确的人工确认

直达率定义为“有效续跑点击中，未经主 Agent 重复路由且成功进入目标活跃子 Agent 的比例”；当前基线与目标均为 [TBD]。

07 / CONTEXT OPTIMIZATION

上下文折叠与 KV Cache 复用

上下文优化由两个相互独立但协同的机制组成：SkillContentCollapseHook 控制历史 Skill 内容体积，静态/动态 Prompt 解耦保护可复用前缀。优化不得改变当前任务所需的语义输入。

7.1 SkillContentCollapseHook

  1. 标记内容。每段 Skill 内容关联 Skill 标识、加载轮次、内容引用和版本/摘要信息；实际元数据字段为 [TBD]。
  2. 计算轮次。加载后达到折叠阈值 N 的历史内容进入候选集合；N、轮次起点和多 Skill 累计方式为 [TBD]。
  3. 保护活跃内容。当前轮次、当前活跃 Skill、被未完成工具调用引用的内容不得折叠；折叠时保留可恢复引用和必要摘要。
  4. 按需恢复。后续任务确需已折叠内容时，按引用重新加载；引用失效则返回可恢复错误，不允许模型猜测原 Skill 输出。
ID要求验收标准
FR-X01超轮次自动折叠超过配置轮次的非活跃 Skill 内容不再以完整原文重复进入后续模型请求
FR-X02活跃语义保护活跃任务、未决工具调用及当前轮次所需内容保持可用；折叠前后任务结果语义一致
FR-X03可恢复引用折叠占位可定位原内容；恢复失败有明确错误和降级路径，不产生虚构内容
FR-X04静态/动态解耦稳定指令与 Skill 静态内容位于可复用前缀；当前时间等动态信息置于独立动态段，不随时间改写静态前缀
FR-X05缓存观测能够按请求关联静态前缀版本、折叠次数、上下文 Token、缓存命中指标；具体埋点能力 [TBD]

正确性优先于缓存命中：凡影响模型语义的动态状态都不能为了复用缓存而留在“静态”段。当前时间只应进入动态段；静态 Prompt 的修改应通过明确版本变更使旧缓存自然失效。

不预设收益数值：上下文 Token 降幅、KV Cache 命中率和端到端延迟收益需用独立实验测量，当前输入未提供相关基线。
