# 差旅业务操作台前端计划

## Context

项目已有 FastAPI 路由、Redis 方案审核、续跑和指标能力，但没有正式产品前端。用户需要可直接浏览和操作的可视化页面，并明确要求不要呈现通用 AI 模板感。已确认采用“业务操作台”和“演示数据 + 真实 API”双模式：默认页面可完整浏览，真实模式只展示后端真实返回，失败时不自动用演示数据冒充成功。

## 推荐实现

### 1. 工程与视觉方向

在 `frontend/` 新建 Vite + React + TypeScript 应用，不引入 UI 框架、图表库、路由库或全局状态库。Vite 将 `/api` 代理到 `VITE_API_PROXY_TARGET`（默认 `http://localhost:8000`），解决开发环境跨域。

产品名采用“行知差旅”，视觉参考纸质行程单、票根和企业差旅台账：暖白背景、纸张表面、墨色文字、低饱和绿和少量陶土色；小圆角、细分隔线、等宽编号、清晰表格。禁止紫色渐变、玻璃拟态、发光、粒子、宣传式 Hero、大面积插画及无意义动态效果。复用 spec 中已有的绿色/暖色设计方向，但不复用其报告页面布局。

### 2. 页面结构

- **左侧导航**：行程工作台、运行指标、API 设置；持续展示“演示数据 / 真实 API”来源标识。
- **工作台顶部**：出差单编号、行程日期、当前阶段和方案版本；演示行程显示“上海 → 深圳”，真实模式没有城市字段时只显示方案 ID，不猜测城市。
- **需求输入**：输入 1–500 字并执行“识别意图”；展示目标 Agent、判定层、置信度、候选分数、trace_id 和澄清信息。明确此操作不会自动生成行程。
- **行程单**：日程、交通候选、酒店候选三个页签；展示时刻、价格、换乘、距离、退改属性和日程引用，统一注明“候选方案，非出票或入住凭证”。
- **审核侧栏**：结论、审核轮次、规则版本、按后端顺序排列的整改项；展示优先级、严重度、维度、重复次数和证据，审核失败不能显示成通过。
- **续跑动作**：确认、修改、重新规划、取消按当前阶段展示；演示模式只推进本地阶段，真实模式完全由 `/v1/continuation/actions` 返回结果驱动。说明确认不等于出票，重规划不等于已生成新方案。
- **运行指标**：路由、审核、续跑计数，平均/P95 延迟，Token 用量和四项比率；采用紧凑表格与 CSS 量尺，不虚构趋势图，注明“当前进程累计”或“演示快照”。
- **API 设置**：模式切换、健康检查、用户/会话/方案及续跑上下文标识。密钥仍只由后端 `.env` 管理，前端不接收模型密钥。

### 3. 文件组织

- `frontend/package.json`、`vite.config.ts`、`tsconfig.json`、`index.html`：工程、构建与代理。
- `frontend/src/main.tsx`、`App.tsx`：应用入口、导航和当前视图。
- `frontend/src/types.ts`：对齐现有 `RouteDecision`、`ItineraryPlan`、`ReviewReport`、续跑和指标契约。
- `frontend/src/api.ts`：真实 HTTP 请求、查询参数和 FastAPI 错误解析；不复用或回退演示数据。
- `frontend/src/demo.ts`：明确标注的本地方案、审核、路由、指标夹具及演示阶段推进，不发起网络请求。
- `frontend/src/components/RequestComposer.tsx`：需求输入和路由回执。
- `frontend/src/components/ItinerarySheet.tsx`：日程、交通和酒店行程单。
- `frontend/src/components/ReviewPanel.tsx`：审核报告、整改证据和续跑动作。
- `frontend/src/views/WorkbenchView.tsx`：组合工作台并管理当前方案、报告、加载及错误状态。
- `frontend/src/views/MetricsView.tsx`、`SettingsView.tsx`：指标和连接设置。
- `frontend/src/styles.css`：完整设计变量、桌面/平板/手机布局、焦点和减少动态效果支持。
- `frontend/src/demo.test.ts`、`api.test.ts`：演示边界、状态推进和 API 请求测试。

### 4. 双模式边界

- 演示模式默认展示一套上海至深圳、三天两晚的真实感数据和本地审核结果；所有演示视图持续可见“演示数据”，不显示为真实模型调用。
- 真实模式默认不载入演示方案，通过 `plan_id + user_id + session_id + 可选 version` 调 `GET /v1/plans/{plan_id}` 读取已有方案。
- 真实路由只更新路由回执，不生成、清空或覆盖行程；真实审核绑定当前方案版本；真实续跑没有活跃会话时显示空动作，不自行伪造按钮。
- 切换模式时清空上一模式的方案、报告、动作和错误，避免演示内容残留到真实视图。
- 真实请求出现 400/404/409/422/503 或网络错误时直接展示；特别是 `healthz` 正常但业务接口 503 时提示依赖未配置，绝不自动切演示。
- 不实现完整自动规划、订票、支付或真实 AgentScope CLI 操作，也不添加无法工作的导航和按钮。

### 5. 响应式与可访问性

桌面采用约 208px 侧栏、主行程区和审核侧栏；中等宽度将审核移到行程下方；手机改为顶部导航和单列布局。交通/酒店信息在窄屏转为纵向组，按钮至少 44px 高；异步反馈使用 `aria-live`，表单有标签、键盘焦点清晰，支持 `prefers-reduced-motion`。

## 验证

1. 执行 `npm install`、`npm run typecheck`、`npm run test`、`npm run build`。
2. 单元测试覆盖：演示模式不调用 `fetch`、真实失败不回退演示、模式切换清理状态、演示阶段动作合法、API 路径与错误解析正确。
3. 启动 Vite 开发服务器，在浏览器检查首屏视觉、页签、意图识别、审核、续跑、指标和 API 设置；确认演示模式没有 `/api` 网络请求。
4. 在 1440、1024、768、390px 宽度验证无页面级横向滚动、信息不重叠、动作可键盘操作。
5. 启动 FastAPI 后验证真实模式：`/healthz` 可达但缺 Embedding 时业务请求如实显示 503；不伪造路由、审核或指标成功结果。
